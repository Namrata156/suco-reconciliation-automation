v3.2 AMENDMENT (2026-10-10)
---------------------------
  - Owner: "we only work on that particular day". Each business date is
    reconciled ONLY against its own files. The system does no cross-day
    check, in either direction. This REVERSES the Q3 answer (next-day
    re-check) for R13.
  - R13 (In CBS only) -> Pending Investigation, MEDIUM, due T+1 (working
    days), on its own business date. A maker investigates (for example, by
    checking the next day's NPCI file by hand) and decides, and a checker
    approves. No refund is suggested automatically. This is the same "no
    automatic money action" approach as R06b.
  - Why not "Reversal Required": on 26 Sep most of the 578 CBS-only
    payments are 27 Sep transactions (RRN day code 270) that NPCI records
    the next day. An automatic refund would pay those customers twice.
  - R12 (NPCI only, successful) is unchanged: Adjustment Required, HIGH,
    T+1.
  - Known effect (Phase 2 Step 5, 2026-10-10): a payment that NPCI
    records on day D and CBS posts on D+1 shows up as R12 on D AND R13 on
    D+1, two separate items. Examples: 11 pairs on 25/26 Sep, and RRN
    656121043209 (Rs 900) on 14/15 Jul. Ops resolves these by hand. R13
    is a review item, so no money moves without a maker decision.
  - Superseded by this amendment: the Step 4 next-day re-check
    (awaiting / matched next day / escalated) and the owner's two
    2026-10-10 decisions about it (only 00/RB clears; escalation deadline
    counts from the escalation date).
  - Rule counts: unchanged (R13 matches the same groups: 1 / 10 / 578).
  - Phase 3 item (owner, 2026-10-10): several Adjustment rows for one RRN
    on one date. Only the first row is evaluated today (example:
    187576707970, 14 Jul).

HOW TO READ THIS
----------------
- Each transaction (one RRN on one business date) is checked against the
  rules from top to bottom. The FIRST rule that fits wins.
- "Status" uses the spec's own categories (docs/reconciliation_automation.docx,
  Business Rule Engine > Exception and Action Classification).
- "Source": SOP = docs/sop_reference.md, Ops note =
  docs/reconciliation_note_photo.jpeg, Spec = requirements doc,
  NPCI / RBI = circulars listed under SOURCES, Owner = project owner's
  decision.
- "TAT" = turnaround time (deadline), counted from the business date.
  "T+1" = next working day.
- "Counts" = transactions per rule on 14 Jul / 25 Sep / 26 Sep.
- Every final action still goes through Maker-Checker (Phase 3). The rules
  only RECOMMEND an action.

GLOSSARY
--------
On-us            : payer and payee both bank with SSK.
Reversed         : CBS debited the customer and then credited the same amount
                   back (same RRN). This matches ops' "rev" check.
Eff / rev        : ops' manual-sheet columns. Eff = found in CBS. Rev = found
                   in the reversal sheet.
SSK side         : the party the SOP says SSK acts on:
                     DRC        : Remitter = SSK
                     Timeout    : Beneficiary = SSK
                     Adjustment : Remitter = SSK
                   In the system this is RegisterPresence.ssk_side.
                   ssk_side = False means "SSK is the OTHER party". It does
                   NOT mean "SSK not involved". Example: all 12 Timeout rows
                   on 25/26 Sep have SSK as the remitter.
Deemed approved  : NPCI response code RB. The beneficiary bank timed out and
                   NPCI settled the credit anyway. The remitter must NOT
                   reverse its customer. The beneficiary bank confirms with
                   TCC or returns with RET.
Declined code    : NPCI response code other than "00" on a transaction that
                   never reached CBS (e.g. Z9, XB, 01, ZM). No money moved.

 AGEING (new - approved 2026-10-09)
================================================================================

  Due date = business date + TAT of the rule that fired.
  Overdue  = today is later than the due date.
  The work queue lists HIGH priority + overdue first.
  RBI compensation (Rs 100 per day) applies after T+1 for unreversed
  customer debits (R02, R05, R12).

  Ageing report buckets (Phase 6), each boundary tied to a real deadline:

    Bucket    Boundary reason
    0-1 d     T+1  : DRC / TCC / RET / reversal (RBI, NPCI)
    2-5 d     T+5  : merchant payment reversal (RBI, UPI 4b)
    6-7 d     7 d  : chargeback raise (ops note)
    8-35 d    35 d : chargeback representment (ops note)
    36-45 d   45 d : customer chargeback window (NPCI OC 198)
    45+ d            past every known deadline

  Source: Owner (Q5c / ageing), 2026-10-09.

Q1. R05 - which RET reason?
    Answer (2026-10-08): The system pre-fills RET 115. The maker may choose
    another SOP reason, and the checker approves. Ops' manual sheet has no
    reason column, so the data could not settle this.

Q2. R07a, R08, R10, R11 - no financial action?
    Answer (2026-10-08): Agreed for all four. Also agreed for the new R04c
    (Timeout where SSK is the remitter).

Q3. R13 - CBS only.
    Answer (2026-10-08): Pending Investigation, re-checked against the next
    business date's NPCI files. Escalate to Reversal Required only if the
    transaction is still missing. The evidence is under R13.

Q4. What does NPCI response code RB mean?
    Answer (2026-10-08): Deemed approved. The remitter must not reverse its
    customer. The beneficiary bank confirms by T+1 with TCC 102/103 or
    returns with RET (by 4 pm). See R04c and R17.

Q5. Priorities and deadlines.
    Answer (2026-10-09):
    (a) The draft priorities are kept.
    (b) DRC 102/103/104, TCC and RET all T+1 (RET by 4 pm), per NPCI
        Circular 17 / OC 93 and RBI/2019-20/67.
    (c) Re-presentment Raise = 35 days. This is unverified, because no
        public NPCI source gives the figure. See Q8.

Q6. "TD 2%" / "BD 8%" on ops' note.
    Answer (2026-10-08): Not a reconciliation rule. Parked for Phase 6 as a
    possible decline-rate monitoring report. Confirm the meaning, and which
    NPCI codes count as technical vs business declines, with ops.

Q7. R06 RET where CBS already shows the reversal.
    Answer (2026-10-09, v3.1): No automatic credit. It goes to
    maker-checker review (rule R06b) with the reason shown. Raise again in
    the Phase 3 Maker-Checker design.

Q8. Re-presentment Raise TAT.
    Answer (2026-10-09, v3.1): Any chargeback-type adjustment more than 35
    days after the original transaction is an Exception, HIGH, flagged to
    the user (rule R07x). STILL TO CONFIRM WITH OPS: the actual response
    deadline for a re-presentment, and whether it counts from the
    transaction date or the re-presentment date. Doesn't block Step 3.
