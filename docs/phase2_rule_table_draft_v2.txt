HOW TO READ THIS
----------------
- Each transaction (one RRN on one business date) is checked against the
  rules from top to bottom. The FIRST rule that fits wins.
- "Status" uses the spec's own categories (docs/reconciliation_automation.docx,
  Business Rule Engine > Exception and Action Classification): Reconciled,
  Exception, Pending Investigation, Reversal Required, Adjustment Required,
  Manual Credit Required, Return Required, Chargeback Required,
  No Financial Action Required.
- "Source":
    SOP      = taken from the bank's SOP (docs/sop_reference.md)
    Ops note = taken from ops' printed note (docs/reconciliation_note_photo.jpeg)
    Spec     = taken from the requirements document's pattern table
    PROPOSED = my suggestion; needs the project owner's decision
- "TAT" = turnaround time (deadline) for the action. "T+1" = next working day.
  "to confirm" = not given in the SOP or the ops note.
- "Counts" = how many transactions fall into the rule on
  14 Jul / 25 Sep / 26 Sep, from the real loaded data.
- Every final action still goes through Maker-Checker (Phase 3). The rules
  only RECOMMEND an action.

GLOSSARY
--------
On-us            : payer and payee both bank with SSK. NPCI shows two rows
                   (issuer + acquirer) and CBS shows a credit and a debit.
                   This is normal, not a reversal.
Reversed         : CBS debited the customer and then credited the same amount
                   back (same RRN), and NPCI does not show a successful on-us
                   pair. (Matches ops' "rev" check in the manual sheet.)
Eff / rev        : ops' manual-sheet columns. Eff = the RRN is found in CBS
                   (effected). Rev = it is found in the reversal sheet.
SSK side         : the side of a dispute the SOP says SSK must act on -
                   DRC: Remitter = SSK; Timeout: Beneficiary = SSK;
                   Adjustment: Remitter = SSK.
Declined code    : NPCI response code other than "00" on a transaction that
                   never reached CBS (e.g. Z9, XB, 01, ZM). No money moved.
Original not     : an Adjustment whose original transaction date (Txndate)
loaded             has not been loaded into the system yet.

Q4. R17 - What does NPCI response code "RB" mean for your bank?
    If it means "deemed approved", these transactions could be Reconciled
    instead of Pending Investigation.
    Answer: ANSWERED 2026-10-08 (project owner approved, from NPCI circulars).
            RB = "deemed approved": the beneficiary bank timed out, NPCI
            settled the credit anyway. The REMITTER bank must NOT reverse
            its customer for RB; the BENEFICIARY bank must confirm by T+1
            with TCC 102/103 or return with RET (by 4 pm, else NPCI debits
            it). Sources: NPCI UPI Circular 17 (2017, Debit Reversals and
            Deemed Approval); NPCI OC 79 FY16-17; NPCI OC 93 FY19-20;
            NPCI UPI OC 213 FY24-25 (chargebacks auto-decided on TCC/RET).
            Effect on R17: an RB transaction in both CBS and NPCI where
            SSK is the remitter is "No Financial Action Required" (wait
            for the other bank's TCC/RET; a RET arrives later in the
            Adjustment file -> R06). Where SSK is the beneficiary, the
            Timeout rules R04a/R04b/R05 already apply first.
            Data check 2026-10-08: every RB transaction found in both
            CBS and NPCI is also in the Timeout file (12 / 6 / 6).
            CORRECTION 2026-10-09: R17's counts above (7 / 0 / 1) were
            right. The 12 / 6 / 6 figure included rows that earlier
            rules already catch (R04a, R06, R07a). See v3.

================================================================================
 WHAT HAPPENS AFTER APPROVAL
================================================================================

Step 3  Build the rule table as data, not code: a versioned rule set that
        the system reads (spec: Rule Repository, Rule Versioning). Changing
        a rule later means a new version, not a code change. Also a
        response-code table holding the codes named in the SOP and the ops
        note (102, 103, 104, TCC 102/103, RET 115, RRC 501).
Step 4  Rule evaluator: applies the approved rules to every transaction of a
        business date and records status, action, priority, reason, code,
        due date (from TAT) and the rule version used. One command runs a
        whole day.
Step 5  Run it on the 3 loaded dates, check against ops' manual sheet,
        update the tracker.
